# Agent Instructions for Xiangshan OpenSBI Linux Kernel

This repository builds a RISC-V Linux system for Xiangshan processor using OpenSBI, Linux kernel 7.0, a minimal rootfs, and board definitions.

## Quick Start

1. Set `RISCV_ROOTFS_HOME=$(pwd)/riscv-rootfs`
2. Build rootfs apps: `make -C riscv-rootfs rootfsimg`
3. Build Linux kernel: `cd linux-7.0 && make ARCH=riscv xiangshan_defconfig && make ARCH=riscv CROSS_COMPILE=riscv64-unknown-linux-gnu-`
4. Build OpenSBI (optional payload): `cd opensbi && make PLATFORM=generic CROSS_COMPILE=riscv64-unknown-linux-gnu-`
5. Generate DTB: use scripts in `nemu_board/dts/` for desired core count.

## Environment Variables

- `RISCV_ROOTFS_HOME`: absolute path to `riscv-rootfs` directory. Required for building rootfs apps and kernel initramfs.
- `CROSS_COMPILE`: RISC-V toolchain prefix (e.g., `riscv64-unknown-linux-gnu-` for kernel, `riscv64-unknown-elf-` for rootfs apps). Defaults in rootfs Makefiles assume `riscv64-unknown-elf-`.

## Building RootFS Apps

```bash
cd riscv-rootfs
make rootfsimg
```

Builds all applications listed in `APPS` and symlinks them into `rootfsimg/build/`. The initramfs source (`initramfs-emu.txt`) expects `hello` binary.

## Building Linux Kernel

1. Ensure rootfs apps are built first (`make -C riscv-rootfs rootfsimg`) because the initramfs source expects the `hello` binary.

2. Set `RISCV_ROOTFS_HOME` before configuring and building:
   ```bash
   export RISCV_ROOTFS_HOME=$(pwd)/riscv-rootfs
   cd linux-7.0
   make ARCH=riscv xiangshan_defconfig
   ```
   The defconfig already exists in `arch/riscv/configs/`. Alternative defconfigs (`xiangshanhost_defconfig`, `xiangshan_overlay_defconfig`) are in `nemu_board/configs/` and can be copied if needed. The variable `${RISCV_ROOTFS_HOME}` in `CONFIG_INITRAMFS_SOURCE` is expanded at kernel build time, so it must remain set during the build.

3. Build kernel:
   ```bash
   make ARCH=riscv CROSS_COMPILE=riscv64-unknown-linux-gnu-
   ```

The resulting Image is at `arch/riscv/boot/Image`.

## Building OpenSBI

OpenSBI can be built with the generic platform, optionally with a Linux payload:

```bash
cd opensbi
make PLATFORM=generic CROSS_COMPILE=riscv64-unknown-linux-gnu- [FW_PAYLOAD_PATH=../linux-7.0/arch/riscv/boot/Image]
```

Firmware images are placed in `build/platform/generic/firmware/`.

## Device Tree Generation

Device tree blobs for different core counts are generated by scripts in `nemu_board/dts/`:

```bash
cd nemu_board/dts
python3 DTSGen.py --nr-harts <N> ... | dtc -O dtb -o build/xiangshan.dtb -
```

Pre‑made scripts (`build_*_core_for_{nemu,qemu}.sh`) wrap common configurations.

## Running the System

The final boot image likely combines OpenSBI firmware (fw_payload.bin), DTB, and possibly an initramfs. Consult board‑specific documentation for the exact QEMU/NEMU command line.

## Notes

- The rootfs apps are built with a bare‑metal toolchain (`riscv64‑unknown‑elf‑`), while the kernel and OpenSBI require a Linux‑capable toolchain (`riscv64‑unknown‑linux‑gnu‑`).
- The kernel defconfig (`xiangshan_defconfig`) points `CONFIG_INITRAMFS_SOURCE` to `$RISCV_ROOTFS_HOME/rootfsimg/initramfs‑emu.txt`. Ensure the variable is set when configuring the kernel.
- Each component (linux, opensbi, riscv‑rootfs, nemu_board) is a separate git repository; changes must be committed in each individually.
